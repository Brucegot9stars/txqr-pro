# QRT2 传输协议

本轮修复采用用户确认的范围：只要求更新后的两端互通。经典 QR / Color Matrix 的旧文本帧不再接收；请同时更新 Go 发送端、Windows 接收端和 Android 接收端。喷泉码的索引、随机数、分片方式和 Online 参数保持原有定义，未替换算法。decimen 仍使用 D1 0D + DCF2，其线格式未改变。

## 经典帧

```
QRT2/session/sha256/code/chunk/total/codec/kind/crc32|payload
```

| 字段 | 定义 |
|---|---|
| session | 每次 Encode 重新生成的 128 位随机值，32 个小写十六进制字符 |
| sha256 | 原始文件的 SHA-256，64 个小写十六进制字符 |
| code | 十进制编码块编号；文件名帧为 -1 |
| chunk | 用户指定的分片参数，不等同于所有算法的实际源块长度 |
| total | 原始文件字节数 |
| codec | 显式 `lt`、`binary`、`raptor`、`raptorq`、`online` |
| kind | `data` 或 `name` |
| crc32 | CRC-32/IEEE，8 位十六进制字符 |
| payload | 原始二进制；name 帧为 UTF-8 文件名 |

CRC 输入为 `QRT2/.../kind` 的 ASCII 字节、一个 `|` 字节、完整 payload；不包含 `/crc32` 本身。所有字段、长度及 CRC 必须先验证，再更新会话、去重缓存和方程状态。CRC 用于检出帧错误，SHA-256 用于核对恢复的原始文件；它们不提供发送者身份认证。

会话身份为 `(session, sha256, chunk, total, codec)`。不同身份的方程绝不混用。Go Decoder / Android TxqrDecoder 由显式 reset 更换身份；Windows 管理层在连续 15 帧来自同一新身份后，清空旧方程再切换，已校验内容等待文件名时禁止切换。文件名是独立元数据，不增加数据块进度。v2.0.6 起每轮在数据序列起点、约三分之一、约三分之二处发送相同文件名帧，总计 3 次；短到只有 1–2 个数据帧时允许末尾补发。数据帧编号、内容和 CRC 格式不变。

内容恢复后，核心解码器仍可接收通过 CRC 及同会话校验的文件名，保留第一个名称。Windows / Android 在缺少文件名时继续扫描约 3 秒，独立检查超时，不要求再收到二维码才能结束。正常已知文件名不增加等待。补收不重新计入编码字节或延长内容恢复耗时；界面显示正在补收，超时保存/建议接收端兜底名称并明确提示。有限次重复和等待不能保证连续丢帧情况下必定拿到文件名。

令 `K=ceil(total/chunk)`。RaptorQ 的数据帧长度为 chunk，最后一个源符号补零；其他模式的非空数据帧长度为 `ceil(total/K)`，发送端将 gofountain 的虚拟尾部零填充显式写入帧。Binary 的空组合允许空 payload。小文件 `total<=chunk` 的 gofountain 模式使用显式 LT 单块帧；Raptor 原有小 K / 本地自检失败回退 LT 的规则保留，元数据使用实际生效的 codec。

接收端必须执行：CRC / 参数验证 → 会话匹配 → 去重 → 加入符号 → 尝试实际求解 → 原始长度及 SHA-256 验证 → 发布完成数据。RaptorQ 的 ready 仅代表可以尝试求解；秩不足时继续接收。长度或 SHA 不匹配进入失败状态，只有重扫才重新使用空白状态。

## 资源边界

Go 与 Kotlin 的经典解析器共用：total ≤ 64 MiB、chunk ≤ 2933、K ≤ 8192、code ≤ 0xffffff；Raptor 的 code ≤ 65535 且 K ≥ 4。独立限制同时生效，例如 split=2048 时最多 16 MiB。文件名最多 360 个 UTF-8 字节；头部最多 160 字节。这些是现有协议参数上限，不是各算法的理论极限。v2.0.1 移除 v2.0.0 新增的接收端工作内存估算拒绝、矩阵/修复符号预算和 `4K+256` 累计帧数拒绝；合法会话按实际需要分配，重复帧仍去重。实际可接收规模受设备可用内存与算法开销影响。上述字段合法性、容器长度、CRC、会话身份和最终 SHA-256 校验继续执行。

Color Matrix 的总载荷仍为 1587 字节，预留 161 字节给 QRT2 头及分隔符，数据 split 上限为 1426。普通 QR 在 ECC M 下仍受二维码容量限制。发送端根据所有帧的最大长度选择固定 version，保留静区和整数模块尺寸。

发送端默认上传上限为 64 MiB，最多保留 4 个会话；实际经典文件上限同时受 `8192 * split` 及二维码容量约束。v2.0.3 的网页显示当前设置、所选文件的可用分片范围及版本，客户端在上传前拒绝不支持的选择，服务端在进入编码 worker 前再次验证。2331 字节是普通 QR ECC M 的整帧容量，包含 QRT2 头，不是可用文件分片长度。24.4 MiB 在当前经典模式没有可用分片范围，需压缩或分卷，不能通过增大 split 解决。

编码请求全局单并发。v2.0.3 默认在短期 worker 中完成喷泉编码和首批最多 64 张 PNG，后续由主进程按播放需求及提前 32 帧的窗口生成。每会话最多 2 个后台预取任务，共享最多 8 个渲染槽；同一帧请求合并。主进程渲染只接受有界帧长度和图像参数（最多 185 模块/边、8 px/模块），不在全局状态锁内计算。它没有 worker 的进程内存硬限制；图像规模和并发上限限制临时开销。单会话 PNG 缓存最多 128 MiB，所有会话帧和 PNG 缓存合计最多 256 MiB，旧 PNG 可淘汰并按需重建。这些缓存值不是整个进程 RSS 上限。选择「先准备整轮」可恢复完整预生成，整轮图像须容纳于准备缓存预算。

喷泉编码和首批/整轮准备仍由同一可执行文件的受限 worker 执行，使用标准输入/输出管道，无新增外部通信。Windows Job Object 限制该 worker 私有提交内存为 512 MiB，并在父进程退出时终止；Linux 使用 RLIMIT_DATA 配合父进程退出信号，已有更低系统硬限制不会提升。请求取消会终止并等待 worker，5 分钟编码期限也会终止库调用。主进程按需渲染的单张有限计算不能在函数内部抢占取消；取消后丢弃结果。会话取消、过期或服务关闭会取消后台预取，服务关闭等待其退出。上传读取期限 30 秒；活跃取帧续租，空闲 30 分钟回收。Windows/Linux 以外的受限 worker 平台仍明确报不支持。

PNG 使用 BestSpeed 无损压缩；二维码模块、调色板像素及整数缩放保持一致。MD5 随序列化结果返回，不再在选择文件时重复上传整份文件计算。发送端记录版本/PID、参数拒绝、编码与准备耗时、首帧响应、慢渲染和错误，正文文件数据不写入日志；网页「发送日志」显示路径及最近记录。日志为当前文件及两个备份，每个约 2 MiB；写盘失败保留有界内存尾部并显示原因。

## 调度与测量边界

Android 由一个后台处理器顺序接收帧批次，只保留一个最新的待处理批次。重扫创建新会话对象；旧任务只能完成自己的计算，不能向新会话回写。解码、解压和校验不在主线程执行，主线程只读取不可变结果快照。

v2.0.1 浏览器每格最多预取三帧，完成 `Image.decode()` 后才在刷新回调中替换显示。沿连续时间轴推进截止时间，避免按抖动后的刷新时间重新计时造成 30→20 / 60→30 FPS 降速；同次刷新允许更新所有到期格子。decimen 保留相位错开，但相位间隔小于屏幕刷新间隔时，多个格子会在同一刷新切换，不声称可产生超出显示器能力的交错次数。慢加载或失败时继续显示上一帧，同一个预取序号退避重试；暂停/取消会终止加载并释放临时 URL。HUD 显示实际替换帧数及观测平均显示率，不能称为文件 Goodput。

Windows 捕获线程只将与上次成功入队图像像素不同的截图送入 QR 识别；队列满时不更新比较基准，后续相同截图可重试。比较使用完整像素而非有碰撞风险的摘要，每次扫描独立保存基准。QR 裁剪在标准 image 类型上共享只读像素，非标准 image 仍复制；RGBA 亮度转换直接读取像素缓冲，保留图像库原有亮度/透明度计算并经逐字节对照测试。v2.0.2 各接收区域优先尝试上次经过协议验证的裁剪/缩放路径，失败后继续原顺序的完整搜索；尺寸变化时不用旧偏好，重置时清除偏好，旧代次禁止发布偏好。单个候选的检测与纯码回退共享只读亮度，各自创建可变二值矩阵。线格式和完整性校验不变。

接收界面的完成平均速度是原始文件字节数除以从首个有效接收帧到校验恢复的时间；不包含发送编码或首次识别前的等待。完整端到端 Goodput 仍需要受控光学测试，不能从这些局部指标直接推导。

## decimen

解析时验证 `0 < totalLen ≤ K*blockLen` 且 `(K-1)*blockLen < totalLen`、blockLen ≤ 2933，以及容器最大长度。只有成功验证整个 DCF2 容器的 FNV-1a、解包后文件长度及 SHA-256，才对外报告成功。FNV 还覆盖文件名及 MIME 等容器内容，但不提供密码学身份认证。失败后停止重复组装/解压，并要求重扫。Android 显式重扫可采用其他会话；Windows 连续 15 个相同新身份的帧可以清空旧状态后切换。

## 共享向量

`txqr/cmd/goldengen` 生成五种 codec 的帧、K=1536 Online 错误恢复反例、K=8192 索引指纹、RaptorQ 欠秩反例、非整除分片和 Color RGBA/PNG fixture。接收端 JVM 测试从仓库 resources 读取，不依赖临时目录文件。

```
cd txqr
go run ./cmd/goldengen ../txqr-reader/android/app/src/test/resources/codecmatrix
```

每次生成会得到新的随机会话，文件内容、编码组合与期望恢复数据保持可验证。该命令仅生成测试数据。
