# v2.0.3：限制、版本、发送准备效率与诊断日志

## 大文件与分片报错

经典模式当前使用最多 8192 个源块。2048 字节分片时，文件参数上限为 16 MiB，而非上传页面允许读取的 64 MiB。普通 QR 使用 ECC M，一帧总容量最多 2331 字节，QRT2 协议头也占容量。不能将整个 2331 字节当作文件分片，更不能通过任意增大 split 处理 24.4 MB 文件。

本轮保持已发布的源块范围与协议。24.4 MB 文件在当前经典模式仍需压缩或分卷；提高 RaptorQ 的大文件支持范围还涉及编码矩阵和跨端扩展性，未通过放大常量宣称解决。

网页现在显示运行版本、上传上限、源块上限、当前实际分片与文件上限、整帧容量、所选文件的可用分片范围及资源边界。参数不支持时，在读取/上传文件前禁用序列化并说明原因。服务端使用编码器的同一组帧字段、文件名处理和码号范围，预估最大帧长，在进入 worker 前再次校验，避免把容量错误延迟到 `QR render failed`。

Windows 主窗口标题和侧栏显示版本，发送页显示常用限制；Android 扫描界面的版本入口可打开限制说明，无相机权限时也可查看。网页版本与 Windows 版本共用 Go 常量，Android 从实际安装包读取版本。Release 工作流检查 Go、Android 和 tag 的版本一致。

## 准备方式与持续速度

过去发送端先生成完整轮播的全部 PNG 才返回。大文件的等待包含了大量尚不会播放到的二维码渲染。

现在提供两种方式：

- **快速开始**：编码仍先完成，在受限 worker 内准备最多 64 张 PNG 后返回；主进程使用两名会话预取任务提前生成接下来最多 32 帧，共享最多 8 个渲染槽。首批缓冲用来吸收生成与显示抖动，同帧请求合并。
- **先准备整轮**：沿用完整预生成，启动等待较长，但在图像缓存充足时播放阶段的生成开销更低。整轮图像须满足缓存预算，超限仍会明确失败。

快速开始不能保证任意机器都能持续 30 FPS。若生成吞吐低于播放需求，缓冲耗尽后实际帧率会下降；云桌面中应比较实际显示率和文件完成时间，必要时选择先准备整轮。

缓存按会话保留 PNG，旧图像可淘汰并重新生成。PNG 上限仍为每会话 128 MiB，所有会话的原始帧与 PNG 合计 256 MiB。计算在全局状态锁外，取消/过期/停止会取消预取并等待其退出。大批喷泉编码与初始 PNG 准备仍使用可终止、512 MiB 上限的隔离 worker；按需 PNG 渲染在主进程中执行，受固定帧长、图像尺寸和并发约束，**没有**该 worker 的独立进程内存硬上限。缓存边界也不是 RSS 上限。

图像优化包含：直接按模块写入相同调色板索引，复制像素行替代逐像素调色板查找；PNG 使用 BestSpeed 无损压缩。原模块矩阵、颜色、缩放、静区和整数居中均保持一致。逐像素/调色板索引对照覆盖负尺寸、过小尺寸、非整倍数尺寸、V1/V40、透明色和相同颜色；PNG 解码后也逐像素对照。未降低 ECC、改掩码选择或替换喷泉算法。

选择文件时不再提前上传整份文件计算 MD5，序列化返回时显示已经计算好的 MD5。有效文件只需上传一次；不支持的选择不会上传或启动编码。

## 日志

网页「发送日志」可刷新最近记录并查看实际日志路径。Windows 通常位于 `%LOCALAPPDATA%\qrt-pro\logs\sender.log`；不可用时尝试临时目录，界面显示最终使用路径。原生诊断页明确区分接收日志与发送网页日志。

记录内容包括版本/PID、服务启动失败、上传/参数拒绝、编码开始、编码与 PNG 准备耗时、首张 PNG 响应、慢渲染、请求/响应错误及 worker 失败诊断。`frame.first` 是服务端首帧响应记录，不代表 Horizon 客户端的首次实际呈现。日志不记录原始文件内容；正常缓存命中不逐帧刷日志。

当前日志及两个备份各约 2 MiB，内存尾部最多 200 条，字段长度有界。写盘失败不会把正常传输改成失败，界面说明写盘错误并保留内存记录。日志不是不可丢失的审计存储，未逐条 fsync。

## 本地证据

Linux amd64、AMD Ryzen 5 5600U、Go 1.25.12。本轮未在本机编译 Windows/Android 产品。

准备基准使用相同 1 MiB 数据、2048 分片、RaptorQ、4 px/模块。计时包括编码和 PNG 准备，不含子进程启动、HTTP 上传或浏览器呈现。每种策略测三次，未同时运行本轮其他性能负载：

| 策略 | 三次耗时 |
|---|---|
| 首批 64 张 | 0.438 / 0.486 / 0.452 秒 |
| 整轮约 1050 张 | 6.659 / 7.230 / 7.120 秒 |

两行使用同一版代码，比较的是策略，不是对旧版本承诺的提速倍数。完整 PNG 冷生成基准连续生成 100 帧、测三次，均值约 21.9 / 22.2 / 21.9 ms/帧；本机单任务具有 30 FPS 的计算余量。它不包含 Horizon、屏幕显示或接收识别，不能据此保证云桌面的 30 FPS 或端到端 Goodput。

PNG 独立基准的同图像样本中，BestSpeed 编码约 3.2–3.9 ms，默认压缩约 6.6–9.0 ms；PNG 从 5470 B 增至 7287 B。压缩级别改变的是本机 HTTP/缓存中的 PNG 体积，解码后图像像素不变；该测量不是整张 QR 的生成时间。
