# QRT Pro v2.0.3

- Windows 主窗口、发送网页和 Android 接收界面显示版本；网页及 Android 提供实际传输限制说明。
- 选文件后计算源块数、整帧容量和可用分片范围，在上传前阻止不支持的参数；服务端进入编码 worker 前再次校验。
- 新增「快速开始」与「先准备整轮」。快速开始先缓冲最多 64 张，再提前生成后续帧；图像缓存可淘汰、重建，同帧请求合并，渲染不再占用全局状态锁。
- 优化二维码模块到像素的绘制，使用 BestSpeed 无损 PNG；回归验证像素、颜色、静区和缩放与原实现一致。
- 去除选择文件时的 MD5 重复上传，复用序列化结果的 MD5。
- 新增发送错误与阶段耗时日志，网页可查看实际路径及最近记录，包含 worker 错误、首帧响应、慢生成；日志轮转有界，写盘失败保留内存记录。

同机 1 MiB/2048/RaptorQ 策略对照：准备首批约 0.44–0.49 秒，整轮约 6.66–7.23 秒。边生成边播放仍要求生成吞吐跟上播放；机器较慢时可选择先准备整轮。Horizon 实际速度需设备复测，详见 [说明及证据](https://github.com/Brucegot9stars/txqr-pro/blob/v2.0.3/docs/sender-v2.0.3.md)。

**24.4 MB 文件在当前经典模式仍需压缩或分卷。** 源块上限 8192，2048 字节分片对应 16 MiB；QR ECC M 总容量 2331 字节包含协议头，增大分片不能无限扩大可传文件。该版本改进前置提示与准备效率，不宣称已经支持更大的经典源块数。

与 v2.0.0+ 的 QRT2 / decimen 协议互通，接收端可继续使用 v2.0.2。Android：versionCode 14 / versionName 2.0.3。升级发送程序后刷新网页，在顶部确认实际版本。

下载：

- `qrt-pro-sender-windows-amd64-v2.0.3.exe`：Windows 独立网页发送服务。
- `qrt-pro-reader-v2.0.3.apk`：Android 接收端。
