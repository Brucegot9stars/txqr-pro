# QRFT 彩色二维码屏幕单向传输优化方案

## 1. 目标

针对 QRFT（QR File Transfer）屏幕隔离单向传输场景：

-   Sender 生成连续播放的数据二维码帧
-   Receiver 截取屏幕区域进行识别
-   无反向通信，无 ACK
-   需要提高单帧数据容量
-   需要保证屏幕、压缩、色彩变化情况下的可靠性

引入彩色编码方案，提高每个模块携带的数据量。

------------------------------------------------------------------------

# 2. 核心设计

## 2.1 Color Matrix 替代传统黑白 QR

传统二维码：

-   黑色 = 0
-   白色 = 1

每个模块：

    1 bit/module

优化后：

使用四种高区分颜色：

  编码   颜色    RGB
  ------ ------- -----------
  00     Black   (0,0,0)
  01     Red     (255,0,0)
  10     Green   (0,255,0)
  11     Blue    (0,0,255)

每个模块：

    2 bit/module

理论容量提升：

    约 2 倍

------------------------------------------------------------------------

# 3. 颜色识别算法

不要简单判断 RGB 最大值。

推荐：

## 3.1 颜色距离分类

定义颜色集合：

    Black  (0,0,0)
    Red    (255,0,0)
    Green  (0,255,0)
    Blue   (0,0,255)

收到像素：

    RGB(r,g,b)

计算欧氏距离：

    distance =
    sqrt(
    (r-r0)^2+
    (g-g0)^2+
    (b-b0)^2
    )

选择距离最小颜色。

优点：

-   抗亮度变化
-   抗色彩偏移
-   比最大分量判断稳定

------------------------------------------------------------------------

## 3.2 饱和度过滤

避免灰色噪声：

    max(R,G,B)-min(R,G,B)<threshold

认为：

    invalid

推荐：

    threshold=40~60

------------------------------------------------------------------------

# 4. 颜色校准机制

每个 QRFT Frame 增加 Calibration 区域。

例如：

    +----------------+
    | R R | G G | B B|
    |              |
    |   DATA       |
    |              |
    +----------------+

Receiver:

1.  读取校准颜色
2.  获取当前屏幕实际 RGB
3.  建立颜色映射表
4.  解码数据区域

解决：

-   显示器差异
-   色彩管理
-   视频压缩

------------------------------------------------------------------------

# 5. 数据帧结构

建议：

    +----------------+
    | Finder Pattern |
    +----------------+
    | QRFT Header    |
    +----------------+
    | Calibration    |
    +----------------+
    | Color Payload  |
    +----------------+
    | CRC/FEC        |
    +----------------+

------------------------------------------------------------------------

# 6. QRFT Header

建议字段：

  字段             说明
  ---------------- ------------
  Magic            QRFT
  Version          协议版本
  Session ID       文件会话
  Frame ID         帧编号
  Color Mode       颜色模式
  Chunk ID         数据块编号
  FEC Type         纠错方式
  Payload Length   有效长度

------------------------------------------------------------------------

# 7. FEC设计

由于：

-   单向通信
-   无 ACK
-   屏幕可能丢帧

必须使用前向纠错。

推荐：

第一版：

    Reed-Solomon

后续：

    LT Code
    Raptor Code

------------------------------------------------------------------------

# 8. 发送策略

采用：

    Sender 无限循环播放所有 Frame

流程：

    File
     |
    压缩
     |
    切块
     |
    FEC编码
     |
    Color Encode
     |
    生成Frame
     |
    循环播放

Receiver：

    持续扫描

    收到完整文件

    提示用户停止发送

------------------------------------------------------------------------

# 9. 压缩支持

Metadata记录：

    Compression:
    None
    Gzip
    Zstd

建议：

-   文本文件使用 Zstd
-   已压缩文件直接发送

------------------------------------------------------------------------

# 10. 性能估算

假设：

100x100 数据模块：

黑白：

    10000 bit/frame

四色：

    20000 bit/frame

30 FPS：

理论：

    600kbit/s
    ≈75KB/s

优化分辨率后：

可达到：

    数百 KB/s

# 12. 推荐实现路线

## V1

-   文件分块
-   Session ID
-   FEC
-   循环发送

## V2

加入：

-   四色编码
-   RGB距离识别
-   自动颜色校准

## V3

演进为：

    QRFT Color Optical Transfer Protocol

成为独立的屏幕光通信协议。

------------------------------------------------------------------------

# 总结

最终推荐方案：

-   四色编码：Black/Red/Green/Blue
-   每模块 2bit
-   RGB欧氏距离分类
-   饱和度过滤
-   Frame颜色校准
-   Reed-Solomon FEC
-   Session ID防混包
-   Sender无限循环
-   Receiver单向恢复

该方案比传统二维码容量提高约2倍，同时保持屏幕传输环境下的高可靠性。
